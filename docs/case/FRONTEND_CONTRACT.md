# Предлагаемый интерфейс и API notFive

Версия предложения: 7 ноября 2026 года. **Эти endpoints и экраны ещё не реализованы.** Перед разработкой сверить формат набора и экспорта с архивом организаторов. Требования: [CONTEXT.md](CONTEXT.md), архитектура: [RESEARCH.md](RESEARCH.md).

## Пользовательский сценарий

Загрузить набор → задать контрольное время в Москве → запустить обработку → увидеть события и причины отбора → проверить источники и журнал → скачать результаты, открыть пост и предпросмотр письма.

Основной вход — файлы организаторов. Интерфейс свободного чата, подключение всех новостных сайтов, подписки и расписание не входят в обязательный MVP.

## Экраны и состояния

| Блок | Содержимое |
| --- | --- |
| Загрузка | Файл, количество записей, ошибки структуры, пропущенные поля; расширения и лимит размера задаёт backend после изучения архива |
| Параметры | Контрольное T и вычисленный интервал `(T−24h, T]`, явно Москва. Для учебного набора T = 07.11.2026 12:00 МСК |
| Запуск | Статус и стадия: проверка входа, извлечение, группировка, отбор, проверка результата, экспорт. Не показывать выдуманный процент |
| События | Номер, заголовок, суть, последствия либо их неизвестность, обоснование места, источники с ID/датами/ссылками |
| Достоверность | Оговорки и противоречия видны рядом с утверждением. Метка «проверено» допустима только с указанием конкретной выполненной проверки |
| Журнал | Все материалы, включая исключённые; фильтр по статусу, группа и причина, ошибка. Удобный переход между событием и исходными статьями |
| Экспорты | Дайджест, пост, предпросмотр письма, скачивание файлов; счётчики знаков возвращает backend |
| Сведения о запуске | Модель/версия, время, число обращений, токены и оценка стоимости; недоступные показатели показывать как «нет данных» |

Различать: корректный результат без событий; 1–4 события с объяснением; успешный результат с пропусками; сбой всего запуска. Ошибка API не является нулём подходящих новостей. Историю и завершённые результаты сохранять после обновления страницы.

Для контрольного прогона результаты доступны только для просмотра и выгрузки, без редактора ручной правки. Повторный запуск создаёт отдельную запись. Позднее ручной редактор возможен для другого режима, но он не должен менять исходный артефакт контрольного прогона.

## Предложение HTTP API

| Метод и маршрут | Назначение |
| --- | --- |
| `POST /api/v1/datasets` | Multipart `file`; проверить формат, сохранить исходный набор, вернуть ID, число записей и ошибки |
| `POST /api/v1/runs` | `dataset_id`, `control_time` с часовым поясом, `profile_id`; вернуть `202` и ID запуска |
| `GET /api/v1/runs/{id}` | Состояние, стадия, период, статистика, outcome и ссылки на результаты |
| `GET /api/v1/runs/{id}/events` | Канонические события с источниками и доказательствами |
| `GET /api/v1/runs/{id}/journal` | Полный журнал с пагинацией при необходимости |
| `GET /api/v1/runs/{id}/artifacts/{kind}` | Скачать сформированный backend файл; `kind` из фиксированного списка |

`profile_id` — именованный серверный профиль с моделью, промптами и настройками. Клиент не передаёт секреты, system prompt или произвольный адрес провайдера. При создании запуска сервер снимет неизменяемую копию настроек. Повтор одного POST после сетевого сбоя защищается ключом идемпотентности.

Предлагаемая форма состояния:

```json
{
  "id": "run_example",
  "status": "completed",
  "stage": "export",
  "outcome": "partial",
  "control_time": "2026-11-07T12:00:00+03:00",
  "period": {
    "start_exclusive": "2026-11-06T12:00:00+03:00",
    "end_inclusive": "2026-11-07T12:00:00+03:00",
    "timezone": "Europe/Moscow"
  },
  "event_count": 3,
  "fewer_than_five_reason": "Подходящих событий с достаточными данными найдено три.",
  "usage": {"input_tokens": null, "output_tokens": null},
  "cost": {"amount": null, "currency": null, "is_estimate": true},
  "warnings": [{"code": "SOURCE_READ_ERROR", "source_id": "article_7"}]
}
```

Это пример формы ответа, не результаты реального прогона. `status`: `queued`, `running`, `completed`, `failed`. `outcome` только у завершённого результата: `nonempty`, `empty`, `partial`; partial означает значимые ошибки обработки, а не нормальное исключение нерелевантной статьи. При `partial` событий также может быть ноль: отдельно показать, что из-за пропусков полнота результата ограничена.

В событии нужны: `event_id`, `rank`, `title`, `summary`, `consequences`, `selection_reason`, `source_ids`, `claims`, `conflicts`. У утверждения: `claim_id`, `text`, `qualification`, `evidence[]` с `source_id` и фрагментом оригинала. У источника: исходные ID, название, URL, дата, тип издателя, атрибуция заявления. Массив связей source/event поддерживает несколько событий в одной статье; CSV при этом остаётся с одной строкой на материал.

Ошибки API имеют стабильный `code`, понятное `message` и при необходимости поля валидации. Неверный файл/параметр возвращает 4xx; окончательный отказ провайдера фиксируется как `failed` с причиной. Frontend не запускает бесконечные повторы. Для MVP достаточно опроса состояния с паузой и остановкой после терминального статуса; WebSocket не обязателен.

## Экспорт и безопасность отображения

Имена `digest.md` и `journal.csv` обязательны. `post.md` и `email.html` предварительные до README архива. Архив ZIP для удобства интерфейса может дополнять, но не заменяет требуемые четыре файла.

Источником истины для лимитов служит backend и затем официальный checker. Счётчик учитывает пробелы и исключает URL; не полагаться на `String.length` JavaScript без согласования Unicode и Markdown-правил. Пост и письмо используют те же события и ссылки, что дайджест. Скачивание выдаёт уже проверенный артефакт, а не заново сгенерированный текст.

Тексты новостей и результат модели недоверенные. Не использовать сырой `v-html`; Markdown очищать от опасного HTML и схем ссылок. Предпросмотр email — безопасная разметка или iframe sandbox без выполнения скриптов. На клиенте нет ключей провайдеров, в том числе в `VITE_*`; в публичные сообщения об ошибке не попадают заголовки авторизации и секреты.

Фронтенд обращается к Symfony по HTTPS. Для GitHub Pages и отдельного backend заранее задать конкретный origin CORS; платные запуски защищаются серверной аутентификацией и лимитами. Если согласована тестовая отправка письма, разрешённые адресаты хранятся в серверной конфигурации отдельно от новостей, отправка не запускается генерацией автоматически.

## Приёмка интерфейса

Проверить загрузку корректного и некорректного набора; отображение T и обеих границ; восстановление активного запуска после reload; 0/1–4/5 событий; partial и failed; доступ к причинам исключения каждой статьи; конфликт и оговорку; скачивание ровно серверных файлов; отсутствие исполнения HTML/инструкций из материалов. Общие восемь содержательных тестов находятся в CONTEXT.md.
